## Análisis Completo: Token Estático Único para Todos los Integradores

### Problema Confirmado (ADM-20, CWE-287, Severidad Media)

**Arquitectura actual vulnerable:**
- `config/yamaha.php:4-6` define un único `YAMAHA_API_TOKEN` compartido por: yamaha-web, cotizador, agendamiento, WordPress, recepción de taller (capa 1)
- Middlewares correctos técnicamente (`hash_equals`, fail-closed, throttle antes de auth) pero **sin sujeto/tenant**
- Tokens separados por integración (Mi Yamaha, ReWeb, Autofin) son **copias del mismo patrón** con su propio secreto

**Raíz del IDOR (BIT-1011):**
1. Ningún endpoint en `routes/api.php` puede acotarse por tenant/distribuidor
2. `seguimiento?email=` expone leads de cualquier distribuidor
3. `transformarSolicitud()` (línea 438) devuelve `extra` **completo** (RUT, renta, datos crediticios)
4. Token estuvo en HTML del backoffice hasta BIT-842: cualquiera que lo viera conserva acceso

### Infraestructura Existente (Base para Solución)

| Componente | Ubicación | Estado |
|------------|-----------|--------|
| `PersonalAccessToken` (SHA-256, abilities, expires_at) | `app/Models/PersonalAccessToken.php` | ✅ Implementado, no usado en APIs externas |
| Guard `recepcion-taller` con `Auth::viaRequest()` | `AuthServiceProvider.php:42-75` | ✅ Revalida por request, verifica rol |
| Columna `abilities` en BD | Migración existente | ⚠️ Se persiste pero **nadie la comprueba** |

### Plan de Remediación (L12-only)

**Paso 1 - Intermedio compatible (rotación por consumidor):**
```php
// config/yamaha.php
'api' => ['tokens' => ['yamaha-web' => ..., 'cotizador' => ..., 'agendamiento' => ..., 'wordpress' => ...]]
```

**Paso 2 - Token por integrador con scopes (HasApiTokens):**
- Un `PersonalAccessToken` por integrador
- Middleware `token.ability:<scope>` verificando `abilities` JSON
- Scopes: `catalogo:read`, `cotizacion:write`, `agendamiento:write`, `seguimiento:read`, `recepcion-taller:full`

**Paso 3 - Recortar `transformarSolicitud()` para externo:**
- Nuevo `transformarSolicitudParaExterno()` con lista blanca (sin RUT/renta/crediticios)

**Paso 4 - Exigir `hash` obligatorio en `seguimiento/{ticket}`:**
- Ya implementado vía `ForzarHashEnSeguimiento` (BIT-1107)

**Paso 5 - Rotar token actual tras despliegue BIT-842**

### Archivos Clave a Modificar
- `config/yamaha.php` → array `tokens` + scopes
- `VerifyYamahaApiAuthorization.php` / `AuthSessionOrApiToken.php` → iterar tokens + verificar ability
- `bootstrap/app.php` → alias `token.ability`
- `SolicitudService.php` → `transformarSolicitudParaExterno()`
- `routes/api.php` → aplicar `token.ability:seguimiento:read`
